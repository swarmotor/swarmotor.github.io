Deployment research report

OpenPI pi0.5 实际部署 FT 路线分析

目标不是罗列名词，而是给出在 Isaac Sim / DROID 风格部署里能执行的训练路线、代码改造、数据契约、算力边界、评估门槛和停损条件。

首选: SFT Full FT 扩展: DAgger / HIL 谨慎: RLFT / PPO / TGRPO 避免: 无 reward 直接 RL
结论 路线架构 方法对比 部署蓝图 数据契约 代码改造 评估协议 14 天计划 来源

1. 结论先行

部署优先级和停损线
最终推荐路线

SFT LoRA smoke -> SFT Full FT -> DAgger/HIL 修失败分布 -> reward 稳定后再做 RLFT。这条路线把“链路是否正确”“模型上限是否足够”“真实 rollout 是否偏移”“是否值得 RL”四个问题分开验证。

2. 实际路线架构

从可跑到可部署
Phase 0: 固定环境与观测接口
冻结 Isaac Sim 场景、相机 prim、机器人 prim、动作维度、action horizon、prompt 集合。任何后续训练都必须复用同一套评估入口，否则无法判断 FT 是否有效。
Phase 1: LoRA smoke SFT
运行 pi05_isaac_lora 的 norm stats 和 1000 step 训练，只看链路：dataloader 成功、loss 打印、checkpoint 保存、policy server 能启动、20 episodes 回评能产出 metrics。
Phase 2: Full FT 正式 SFT
在同一数据集和评估协议下运行 pi05_isaac_full。Full FT 才是判断数据价值的主结论，因为 OpenPI DROID 文档明确提示 LoRA 便宜但他们暂未发现策略效果好。
Phase 3: DAgger / HIL 失败状态闭环
对 Full FT checkpoint 做 rollout，保存失败前 3-8 秒窗口、人工/teleop 修正动作，将修正片段并回训练集。下一轮仍用 scripts/train.py 做 SFT，不先写 RL。
Phase 4: RLFT / PPO / TGRPO 试验线
只有当 success/failure、阶段奖励、reset、并行 rollout 都稳定时才启动。RLFT 需要新训练脚本，不是改 TrainConfig 就能完成。

3. 方法对比表

部署视角而非论文视角
路线训练信号现有 OpenPI 支持数据要求推荐度部署判断
SFT LoRA 专家动作监督 已有 LoRA variant、freeze filter 和训练路径 LeRobot/RLDS + norm stats 高，但只作 smoke 用来发现字段、shape、动作缩放、checkpoint 问题，不作为最终效果上限。
SFT Full FT 专家动作监督 已有 JAX 训练路径；PyTorch 路径不支持 LoRA/EMA 等特性 高质量成功示教 + 固定评估协议 最高 正式 benchmark 主线。若 Full FT 都不提升，先查数据和评估，不要转 RL。
DAgger / HIL policy 失败状态上的专家修正动作 训练可复用 SFT；采集和合并数据需新增脚本 rollout 记录 + 修正动作 + episode 元数据 最高的非 SFT 扩展 最适合真实部署，因为它直接修正 compounding error 和分布偏移。
Preference FT 轨迹/片段偏好 无开箱训练脚本 成对 rollout 视频、偏好标签或 desirability 标签 中 适合人能判断好坏但难逐步标动作的情况；flow action head 需专门 loss。
Reward-model FT learned reward 或 VLM reward 无开箱训练脚本 视频、语言、成功/进度/偏好标签 中 适合规则 reward 写不清时；必须先验证 reward 与人工成功率相关。
RLFT / PPO / TGRPO online reward、advantage、KL 约束 无开箱支持 并行环境、reward、trajectory store、reset、安全边界 中低，后置 潜力大但改造重。没有稳定 reward 时会把工程问题放大。

5. 数据契约

不满足这些就不要训练

示教数据

  • 每条 episode 必须绑定 task prompt、seed、场景版本和相机配置。
  • action 维度必须等于 config 的 action_dim，horizon 与 policy 输出一致。
  • 图像 key 必须和 DroidInputs 或自定义 policy inputs 完全匹配。
  • norm stats 按 config 计算并随 checkpoint 保存。

DAgger 数据

  • 保存 policy 进入失败状态前的上下文，而不是只保存人工修正后的成功片段。
  • 明确区分 policy_action 与 corrected_action。
  • 记录 intervention start/end，用于切分可训练窗口。
  • 保留失败标签：reach、grasp、lift、place、collision、timeout。

RLFT 数据

  • 每步 reward、done、success、truncation reason 必须落盘。
  • 保存 old policy action logprob 或可复算 logprob 的采样状态。
  • 保留 reference policy 版本，KL 约束要可追溯。
  • 每次 update 后立即跑固定 eval seeds。

6. 代码改造地图

哪些能复用，哪些必须新增
模块现状SFT/DAgger 需要RLFT 需要

scripts/serve_policy.py 可从 checkpoint 启动 websocket policy。 用于 base/LoRA/Full/DAgger checkpoint 回评。 rollout collector 可调用 policy server，但训练端仍需记录 logprob/reward。
examples/isaac_sim/ 本地计划中作为 rollout/eval 入口。 增加 episode recorder、failure tagger、LeRobot delta exporter。 增加 parallel env runner、reset controller、reward calculator。
src/openpi/models/pi0_config.py get_freeze_filter() 定义 LoRA 冻结逻辑。 LoRA smoke 必须确认 model variant 和 freeze_filter 一致。 RLFT 若只调 LoRA，也应沿用 freeze_filter 限制更新范围。
最小 DAgger 改造

先不要改训练 loop。只新增 rollout recorder 和 dataset merger，把修正后的片段转成现有 LeRobot 数据格式，然后继续用 scripts/train.py。

最小 RLFT 改造

必须新增 train_rlft.py。如果没有 old logprob、KL reference、reward audit 和 eval gate，PPO/TGRPO 结果不可解释，也不适合部署。

7. 评估协议与 Go / No-Go

防止把波动当提升

固定评估协议

  • 固定 100 episodes：同一场景版本、同一初始状态池、同一 prompt 列表、同一 camera pose。
  • 每个 checkpoint 至少跑 3 个 seed 子集，报告 mean、std、worst bucket。
  • 记录 stage success：reach、grasp、lift、transport、place，而不是只看最终 success。
  • 每条失败必须落到 failure taxonomy，无法分类的失败不得超过 10%。
  • 评估命令必须和训练 run id 绑定，避免 checkpoint/config 错配。

Go / No-Go 标准

LoRA smoke -> Full FTcheckpoint 可 serve，20 episode 无接口错误。
Full FT -> DAggerFull FT 明显优于 base，且失败集中在 1-3 类。
DAgger -> 第二轮 Full每类失败有足够修正片段，数据质量人工抽检通过。
进入 RLFTreward 与人工成功判断一致，reset 和并行 rollout 稳定。
停止 RLFTKL 飙升、base 能力退化、reward 高但人工 success 不升。

8. 风险矩阵

失败模式和处理动作
风险表现优先排查处理动作
数据字段错配训练能跑但动作无意义observation key、RGB/BGR、camera pose、action scale回到 LoRA smoke，随机抽 20 帧对齐观测和动作。
norm stats 错policy 输出幅度异常assets 目录、asset_id、state/action 分布重新计算 norm stats，并与 base/dataset 分布对比。
LoRA 假阴性LoRA 效果差但 Full FT 有效freeze_filter、rank、训练步数不要因此否定数据，按计划进入 Full FT。
评估波动单次 success 大起大落seed、初始物体位置、仿真 reset增加 episode 数和分桶统计，只比较同一协议。

RL reward hackingreward 上升但成功率不升reward 定义、阶段权重、终止条件冻结 RLFT，回到 DAgger 或重写 reward。

9. 14 天执行计划

按最短可验证路径安排
Day 1-2: 冻结协议
固定 Isaac Sim 场景、相机、prompt、episode seeds、metrics schema；产出 eval_protocol.md 和 base checkpoint 100 episodes 报告。
Day 3-4: LoRA smoke
计算 norm stats，跑 1000 steps，serve checkpoint，20 episodes 回评；只修接口问题，不调模型。
Day 5-7: Full FT v1
跑 pi05_isaac_full 30000 steps；每 5000 steps 保存并抽测；选最佳 checkpoint 做 100 episodes。
Day 8: 失败聚类
把失败按 stage 分类，挑 top 3 failure buckets；如果失败随机分散，先修数据/评估，不进入 DAgger。
Day 9-11: DAgger 采集
对 top failures 做 teleop/人工修正，至少每类 20-50 条修正片段；导出 LeRobot delta dataset。
Day 12-13: Full FT v2
用原始数据 + DAgger delta 继续训练；对比 v1 和 v2 的 stage success。
Day 14: RLFT 立项门
只有当 DAgger 后仍存在可 reward 化的稳定失败，才写 RLFT 设计；否则继续 DAgger 数据闭环。

项目事实 + 外部研究

本项目证据

外部研究证据

DAgger, PMLR 2011

说明 imitation learning 在顺序决策里会遇到分布偏移，数据聚合可缓解误差累积。

What Can RL Bring to VLA Generalization?

比较 SFT、PPO、DPO、GRPO，指出 PPO 对 VLA 泛化和执行鲁棒性更有效。

ConRFT

离线 BC/Q-learning + 在线 HIL 的 VLA reinforced fine-tuning，强调安全和样本效率。

TGRPO

用多阶段 dense reward 和轨迹/step 双层 advantage 做 VLA 在线 RLFT。

VLP

学习 vision-language preference model，为 embodied manipulation 提供偏好反馈。

ReWiND, CoRL 2025

从少量示教学习 language-conditioned reward，再做离线和少量在线适配。
