VLA Post-training Note

从 LoRA 验证到 Isaac Sim 闭环评测：我怎么设计 VLA 后训练路线

我把这条路线拆开看之后，发现 LoRA、Isaac Sim、VLM QA、DAgger 和 World Model 并不是几件并列的工具。它们更像一条后训练流水线里的不同闸门：先确认数据和接口是真的，再让策略进入自己制造的状态分布，最后把失败变成下一轮数据。

LoRA FTIsaac SimRollout FeedbackDAggerVLM / WM QA

我为什么不直接做全参数微调

如果一开始就跑全参数微调，训练成本会把很多基础错误掩盖掉。模型没提升，可能是数据太少，也可能是相机 key 错了、action 维度错了、norm stats 没对齐，甚至是 Isaac 端实际执行的控制语义和训练数据完全不是一回事。

LoRA 在这里不是最终方案，而是烟雾测试。它便宜、快、失败得早，适合帮我确认这条链路是否值得继续投入。只要 LoRA 阶段能稳定暴露和修正数据契约问题，后面的全参数训练才有意义。

先看数据能否进入模型LeRobot 字段、observation schema、state/action 维度、单位和顺序必须先被确认。
再看策略能否被调用policy server 要能用固定请求格式返回动作，而不是只在训练脚本里跑通。
最后看动作是否可执行Isaac 端执行的是末端 delta、joint velocity 还是别的控制接口，这件事不能模糊。

Isaac Sim 在这条路线里不是展示器

我更愿意把 Isaac Sim 当成策略行为的测试台。真实场景重建出来的 mesh、3DGS、点云和相机位姿，只是资产入口；只有当这些资产变成可 reset、可交互、可记录 rollout 的世界，它才开始对 VLA 后训练有价值。

第一人称视角联通测试的价值也在这里。它不是为了证明画面好看，而是为了检查训练时看到的图像、仿真时拿到的 observation、policy server 返回的 action、Isaac 端执行的控制量是否处在同一个闭环里。

我会把“能加载场景”和“能做 benchmark”分开验收。前者只说明资产可见，后者才说明它能参与训练反馈。

我真正想捕捉的是 compounding error

离线 imitation learning 学到的是专家轨迹附近的状态-动作映射。真实 rollout 里，策略会不断把环境推向自己造成的新状态。一个很小的早期偏差，可能让后续图像、物体姿态和接触状态都偏离训练分布，然后错误继续累积。

所以我不会把 benchmark 设计成只验证成功轨迹。它必须允许 policy 进入偏离状态，并且记录偏离之后发生了什么。只有这样，rollout feedback 才不是一句口号。

我观察的失败它通常说明什么下一轮补什么
接近目标时轨迹逐渐偏掉训练数据只覆盖专家附近状态加入扰动初始位姿和恢复轨迹
目标识别对了，但接触后滑走视觉语义成功不等于动力学成功补充接触片段、摩擦扰动和失败标注
夹爪开合时机不稳定长轨迹里的关键监督太稀疏围绕子任务节点截短片段并加权
失败样本混入后性能反而下降新数据没有质量过滤引入 VLM/WM critic 或 advantage filtering

我会按三段推进

Phase 1

LoRA FT + VLM QA + 人工校准

目标是证明数据、policy server、Isaac client 和评测脚本能闭合。VLM 负责语义层面的初筛，比如目标是否被操作、任务是否接近完成；人工校准负责纠正 VLM 在遮挡、接触和边界状态上的误判。

Phase 2

全参数 FT + rollout feedback + DAgger

当输入输出契约稳定后，再进入全参数微调。这个阶段我会把 policy-induced distribution 放进训练：让策略自己 rollout，记录失败状态，再用人工、脚本或专家策略补上纠正动作。

Phase 3

World Model / RECAP-style filtering

数据越来越多以后，问题会从“有没有数据”变成“哪些数据值得学”。World Model 更适合判断动力学风险，RECAP-style value 或 advantage filtering 更适合把高价值片段从混合数据里挑出来。

VLM 和 World Model 我不会混着用

VLM 适合做语义判断：指令有没有完成，目标物体是不是对的，场景状态是否符合语言描述。World Model 更适合做动力学判断：动作是否可能导致碰撞，未来几步是否偏离目标，接触之后是不是会失败。

我更想要的是 hybrid critic。VLM 给任务语义分，World Model 给动作风险和未来状态误差，两者一起决定一条 rollout 是直接进训练、需要人工复核，还是只作为失败案例保留。

VLM QA看语义完成度、目标对象、阶段进度和明显失败。
World Model QA看短期状态预测、碰撞风险、恢复可能性和动力学合理性。

我会先冻结这些东西，再谈并行化

成熟流程并行化之前，我会先冻结接口。否则每一轮训练和评测都不可比较：这次换了相机，下次换了 action space，再下一次换了 reset 条件，最后只剩一堆无法解释的 success rate。

冻结项为什么必须先定
observation schema保证训练、推理、评测看到的是同一组输入。
action space保证模型输出和 Isaac / 机器人控制接口语义一致。
camera layout减少训练视角和 rollout 视角之间的人为 domain gap。
norm stats 与 policy config避免同一个 checkpoint 在不同配置下被错误解释。
reset、扰动和评测指标让不同训练轮次的 benchmark 可以比较。

这篇路线的核心判断

我不把 LoRA、全参、DAgger、VLM QA、World Model 和 RECAP 看成互斥选项。它们分别处理不同阶段的瓶颈：LoRA 解决低成本验证，全参解决容量，rollout feedback 解决分布偏移，DAgger 解决恢复数据，VLM/WM critic 解决评测密度，RECAP-style filtering 解决数据利用效率。

真正要做的是把它们接成一条闭环：训练、评测、识别失败、生成针对性场景、补充数据、重新训练，再回到评测。

我会刻意少写“最终方案”。这条路线更像研发 pipeline 的骨架，价值在于每一轮失败都能留下可复用的数据和判断标准。
