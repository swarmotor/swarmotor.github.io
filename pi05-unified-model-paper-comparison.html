三篇论文对比：统一 pi0.5 模型视角

GASE / SimFoundry / VLK：数据到手后的训练-评测 pipeline 表格版。固定模型，比较数据、监督、训练、评测与创新点。

1. 统一假设：只比较 pipeline，不比较模型能力

维度统一设定
下游模型统一视为 pi0.5 / pi0.5-style VLA；忽略原论文中不同策略架构差异。
比较对象不是谁的 backbone 更强，而是谁给 pi0.5 提供更好的数据、任务分布和评测闭环。
输入侧统一考虑 image + language + robot state；差异在场景来源和监督信号构造。
输出侧统一讨论 pi0.5 如何被适配到动作、轨迹或 kinematics，而不是只看原始 action head。
研讨重点得到数据后：如何生成样本、如何 fine-tune、如何评测、创新点在哪里。

2. 总览表：三篇论文在统一 pi0.5 pipeline 中的位置

论文pipeline 角色给 pi0.5 的核心价值主要短板
GASE高保真 real-to-sim 场景源。提供低 sim-to-real gap 的训练/测试环境。不负责大规模任务扩增；不定义 VLA 数据格式。
SimFoundrydigital twin/cousins 数据平台。把单场景扩成 object/scene/task 分布，并提供 sim eval proxy。更偏系统平台；pi0.5 action schema 仍需适配。
VLKFT pi0.5 的监督数据与部署闭环。把 synthetic interaction 转成 image-language-state-future-kinematics 数据。任务范围集中在 humanoid loco-manipulation。

3. 数据产物对比：得到数据/场景后到底有什么

论文直接产物可转成 pi0.5 样本吗？需要补的模块
GASE3DGS 背景 + 物体资产 + Isaac Sim 场景。可以，但需要额外收集 demos / rollouts。任务生成、示教生成、VLA action 标注。
SimFoundrydigital twin + object/scene/task cousins + sim-ready assets。更适合，可以批量生成多样任务轨迹。统一成 pi0.5 数据格式和动作空间。
VLKegocentric image + instruction + G1 state + future kinematics + contact label。最直接，论文就是从 pi0.5 初始化微调。若换机械臂/移动底盘，需要重定义 kinematic/action schema。

4. 训练 pipeline 对比：统一 pi0.5 后怎么 FT

论文pi0.5 输入pi0.5 输出/监督训练方式
GASEsim/real RGB + language + robot state。原论文偏任务 action；统一视角下需构造成 pi0.5 action chunk。在 GASE 场景中采样 demos 后做行为克隆/FT。
SimFoundrycousins 中的多场景 RGB + language + state。可定义 end-effector action / joint action / trajectory chunk。用 object/scene/task cousins 做多分布 FT 或 sim+real co-training。
VLKegocentric RGB + instruction + G1 kinematic state。未来 1 秒 whole-body kinematic trajectory + contact label。从 pi0.5 初始化，flow matching / x0 prediction 微调。

5. 评测 pipeline 对比：统一 pi0.5 后怎么证明有效

论文sim 评测real 评测最适合报告的指标
GASEpi0.5 在 reconstructed Isaac Sim 场景成功率。同任务真机成功率；对比 real-data FT。sim2real gap；sim2sim / sim2real / real2real success rate。
SimFoundrypi0.5 在 twin/cousins 上批量评测和排序。少量真机验证策略排序是否一致。Pearson correlation；rank violation；cousins 带来的提升。
VLKpi0.5-style VLK 在 3DGS replica 内闭环执行。Unitree G1 真机导航/搬运/长程任务。任务成功率；数据量 ablation；domain randomization ablation。

6. 创新点对比：固定 pi0.5 后，创新还剩什么

论文不是模型创新，而是...对 FT VLA 的可复用点
GASE高保真、可交互、低 gap 的 real-to-sim 场景构造。用真实重建场景替代廉价但失真的仿真场景。
SimFoundry从 twin 到 cousins 的数据分布扩增 + sim eval 可信度。为 pi0.5 构造 object/scene/task 泛化 curriculum。
VLK把合成交互组织成 pi0.5 可学的 kinematic supervision。重定义 VLA action space：future trajectory 而非 low-level command。

7. 如果做自己的 pi0.5 FT pipeline：三篇怎么组合

阶段借鉴论文具体做法
场景来源GASE用 2D segmentation + inpainting + 3DGS 得到低 gap Isaac Sim 场景。
数据扩增SimFoundry围绕同一 affordance 生成 object/scene/task cousins，避免 pi0.5 过拟合单场景。
监督格式VLK把 rollout 转成 image + language + state + future trajectory/contact 的 paired data。
模型训练VLK + pi0.5从 pi0.5 初始化，替换/适配 action head，FT 到目标 embodiment。
评测闭环SimFoundry + GASE先看 sim-real correlation，再做真机 success rate 与 gap 分析。

8. 主持讨论问题：表格化推进

讨论点可追问的问题
数据pi0.5 更缺 high-fidelity scenes，还是 diverse cousins？
监督未来 trajectory chunk 是否比原始 action 更适合 VLA FT？
模型统一 pi0.5 后，三篇的差距是否主要来自数据 pipeline？
评测sim-real correlation 能否成为 pi0.5 checkpoint selection 标准？
复现最小可行系统应先做 GASE 场景、SimFoundry cousins，还是 VLK 数据格式？

9. 结论表：统一 pi0.5 视角下的最终判断

论文一句话 takeaway
GASEpi0.5 需要可信训练场：GASE 解决 sim 是否足够像 real。
SimFoundrypi0.5 需要泛化分布和评测代理：SimFoundry 解决数据是否足够多样、评测是否可信。
VLKpi0.5 需要合适监督格式：VLK 解决 synthetic interaction 如何变成可微调、可部署的 VLA 数据。
总判断固定模型后，创新点主要转移到 data pipeline、action representation 和 evaluation loop。
