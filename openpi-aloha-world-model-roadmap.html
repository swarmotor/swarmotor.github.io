1. 概念与证据边界

组件输入 -> 输出在本项目中的角色
VLA policyimage + language + robot state -> actionOpenPI pi0.5 产生 ALOHA 14D 外部动作。
State world modelstate + action -> future state/reward/contact首个可验证 evaluator；不直接控制机器人。
Video world modelimage/video + action -> future image/video第二阶段；解决视觉、物体遮挡和接触的可解释性。
World Action Modelobservation + language -> future observation + action研究方向；不应混入第一版 ALOHA evaluator。
Critic / evaluatortrajectory -> score + evidence + counterfactual本路线的目标：找动作问题，而不是替代 policy。
ALOHA MuJoCo rollout -> simulator truth: state, cube pose, contacts, reward, action -> offline state world model: action-conditioned future prediction -> candidate perturbations: gripper delay, joint noise, hold action -> MuJoCo snapshot replay: verify ranking and causal hypothesis -> structured critic report -> optional VLM/LLM: turn verified evidence into natural language
硬边界：MuJoCo 是 ALOHA 任务事实的裁判。世界模型未通过 replay 验证前，只能输出预测或不确定性，不能声称“某个动作导致失败”。Ctrl-World 原生 DROID 复现成功，也不能证明它适用于 ALOHA 双臂 MuJoCo。

为什么 ALOHA 外部 14D、pi0.5 内部 32D 仍然正确

ALOHA 的双臂接口是 14D：左臂 6 joint + 左 gripper + 右臂 6 joint + 右 gripper。pi0.5 checkpoint 的内部 action/state projection 是 32D。AlohaInputs 和 AlohaOutputs 负责 14D 与 32D 的 padding/truncation，必须保持该契约；不要为了“对齐维度”把 model action_dim 改成 14。

3. Track A：DreamerV3 学习 sandbox

DreamerV3 是理解世界模型闭环的最佳学习入口：encoder、RSSM、reward predictor、continue predictor、imagined rollout、actor-critic 都在一个系统中。它的 replay buffer 来自环境交互，而不是预先下载的机器人数据集。

隔离原则：在独立目录和独立环境运行。Dreamer 的奖励、reset、action space 和训练结果不能视为 OpenPI/ALOHA 结果。

环境与最小 debug

cd ~/third_party/dreamerv3
python -m pip install -U -r requirements.txt

# 用户主动运行：最小调试
python dreamerv3/main.py \
  --logdir ~/logdir/dreamer/debug \
  --configs crafter debug \
  --run.train_ratio 32

正常 Crafter 训练与日志查看

# 用户主动运行：正常训练
python dreamerv3/main.py \
  --logdir ~/logdir/dreamer/crafter \
  --configs crafter \
  --run.train_ratio 32

python -m pip install -U scope
python -m scope.viewer --basedir ~/logdir --port 8000

三个学习实验

  1. 跑 debug，确认 replay、world model、imagined rollout、actor-critic 完整链路存在。
  2. 修改 --jax.platform cpu 或 batch size，记录 replay 吞吐、编译时间、显存/内存变化。
  3. 导出 imagined rollout 与真实 rollout，观察预测在哪个 horizon 开始漂移，并记录对应 reward/terminal 偏差。

完成标准：不是获得高分，而是能指出一条真实 trajectory 与 imagined trajectory 在何时、哪个 state/reward signal 上分叉。

4. Track B：TD-MPC2 连续控制 sandbox

TD-MPC2 更贴近连续控制和模型预测控制：latent dynamics、reward/value prediction、短 horizon action-sequence scoring。它是理解“世界模型如何评价候选动作”的好对照，但不应直接复用到 ALOHA action/state space。

7. Track E：ALOHA 离线 state world-model critic

这条轨道解决的是“动作有什么瑕疵、为什么可能失败”。第一版不训练像素世界模型，而是训练 action-conditioned privileged-state dynamics，因为它可以与 MuJoCo object/contact 真值直接比较。

7.1 必须新增的 transition artifact

data/aloha_sim/offline_eval/<run_id>/
  run_manifest.json
  episodes/
    episode_000000.npz
    episode_000001.npz
  metrics.jsonl
  videos/

每个 episode 至少保存下列时序对齐数组：

字段shape用途
policy_state[T, 14]VLA 实际可见的 ALOHA state。
action_applied[T, 14]环境实际执行的 action，不是仅保存 policy chunk。
robot_qpos/qvel[T+1, 14]MuJoCo robot truth。
cube_pose[T+1, 7]red cube world pose。
contacts[T+1, 3]cube-left finger、cube-right finger、cube-table。
reward/terminated/truncated[T]task stage 与 episode boundary。

运行时 callback 顺序是 observation_t -> action_t -> env.step -> subscriber。因此环境必须缓存 post-step ground truth，subscriber 才能正确写出 (s_t, a_t, s_t+1)。

7.2 最小 dynamics model

x_t = [robot_qpos_t, robot_qvel_t, cube_pose_t, contact_flags_t]
a_t = applied ALOHA action_t
model(x_t, a_t) -> distribution(x_t+1 - x_t)

auxiliary heads:
  P(reward stage 0..4)
  P(terminated / success within horizon)
  ensemble disagreement

第一版可以是小型 PyTorch residual MLP ensemble。不要放进 src/openpi/training/config.py，不要通过 serve_policy.py，不要让它改写 policy action。

7.3 验证顺序与停止条件

  1. 按完整 episode seed 切分 train/validation/test，禁止按 frame 随机切分。
  2. 先打败 persistence baseline：x[t+1] = x[t]；再比较 constant-velocity baseline。
  3. 报告 1/5/10/20-step robot/cube error、reward-stage precision/recall、NLL 与 calibration。
  4. 若 object/cube 预测不优于 baseline，不做 action-cause 解释；只保留 simulator rule critic。
  5. 若 ensemble uncertainty 与实际 error 不相关，不能用低不确定性作为可靠性判断。

7.4 反事实候选与 MuJoCo replay

behavior action
right/left gripper delay: +/- 5, +/- 10 steps
action scale: 0.8, 0.9, 1.1
hold gripper open / closed
single-joint +/- perturbation
short temporal hold / time shift

每个 candidate 都必须在同一 MuJoCo snapshot replay 中重放。world model 可以预测排序，但真实 replay 才能验证排序。初始目标：

  • 至少 100 个 held-out branch points。
  • candidate utility 预测与真实 replay utility 的 Spearman correlation >= 0.60。
  • top-1 candidate 与真实最佳 candidate 的一致率至少 60%。
  • 扰动变大时，uncertainty 不应自信下降；若自信错误，则禁止因果归因。

8. Track F：Ctrl-World 外部复现

Ctrl-World 是 action-conditioned generative video world model。公开 checkpoint 来自 DROID/Franka、真实多视角场景；当前 ALOHA 是双臂、top-only MuJoCo。两者在 embodiment、camera、action/state space、domain 上都不匹配。

正确结论语言：“Ctrl-World 官方 DROID pipeline 在指定 commit/checkpoint 下可运行。”
错误结论语言：“Ctrl-World 能评价 ALOHA。”后者需要独立 ALOHA adapter、transition metrics 和 MuJoCo replay 才能成立。

8.3 Ctrl-World 原生复现验收

  1. 记录 official repo URL、commit SHA、license、checkpoint source、benchmark/domain、预处理和官方 metric。
  2. 运行官方 smoke test，再运行 released checkpoint inference/replay。
  3. 用预先声明的 seed 数和官方 metric 对比，标注 reproduced / partial / failed。
  4. 所有输出保存在 data/external_ctrl_world/<commit>/<experiment>/，不写入 data/aloha_sim。

8.4 ALOHA feasibility gate

原生 DROID 复现成功后，才能研究 ALOHA 视频/action 是否可进入 Ctrl-World。需要独立验证：

  • 14D 双臂 action/state encoding 是否有明确、可测试的映射。
  • top-only camera 是否需要补充 wrist/multi-view，或是否有实验支持去除 multi-view。
  • 不同 action chunks 是否导致可区分的 future prediction。
  • Ctrl-World uncertainty/predicted progress 是否与 MuJoCo reward/cube pose 相关。
  • 所有动作 attribution 是否通过 snapshot replay。

10. 证据清单与实验报告模板

每次实验必须保存

  • git revision、配置名、checkpoint 路径/hash、norm stats path。
  • 环境版本：Python、PyTorch/JAX、CUDA、MuJoCo/gym-aloha、GPU。
  • task、prompt、action horizon、max episode steps、固定 seed list。
  • train/validation/test split manifest；禁止 frame-level leakage。
  • videos、metrics.jsonl、transition NPZ、world-model prediction、replay outcome。
  • 通过/失败的验收项与明确限制。

最终 report 的最小结构

{
  "policy": "pi05_aloha_sim_lora:checkpoint_999",
  "task": "gym_aloha/AlohaTransferCube-v0",
  "seed": 3100531970,
  "success": false,
  "max_reward": 2,
  "first_failure_step": 84,
  "simulator_facts": [],
  "rule_diagnoses": [],
  "counterfactual_predictions": [],
  "mujo_replay_validation": [],
  "world_model_uncertainty": 0.31,
  "limitations": ["Candidate B was not replay-validated"]
}

不能用的结论：单条视频成功、训练 loss 下降、checkpoint 保存成功、world model 画面看起来合理、Ctrl-World 原生 demo 成功。

可以成立的结论：固定 seed 的 MuJoCo paired evaluation 显示 success/reward 提升；或 held-out replay 验证了明确的 action counterfactual 排序。
