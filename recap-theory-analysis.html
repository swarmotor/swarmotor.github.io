RECAP theory notebook

RECAP 理论工作具体分析

这份 HTML 把 RECAP 拆成可学习、可实现、可诊断的对象：从离线 RL 的目标函数，到 return/value/advantage 的数学含义，再到 CFG 如何把“高优势”变成推理时的行为偏置。重点不是复述教程，而是解释每个变量为什么存在、错了会怎样、该看什么现象。

一句话定义

RECAP = 用离线数据训练价值函数，再用优势标签训练一个能区分“普通行为”和“改进行为”的策略。 它避免直接在大 VLA 上做脆弱的在线策略梯度，把 RL 问题改写成更接近监督学习的 advantage-conditioned policy extraction。

Problem formulation

1. RECAP 解决的不是“怎么训练策略”，而是“怎么从已有混合数据中抽取更优策略”

真实机器人和大 VLA 的核心矛盾是：你想用 RL 提升策略，但不能像仿真 Atari 那样无限在线采样；你有的数据又很混杂，里面包括人类演示、旧策略成功轨迹、旧策略失败轨迹、甚至人类接管纠正。RECAP 的做法是把这些数据统一看成一个参考策略的数据分布，然后问一个更具体的问题：

给定数据 D = {(o_t, a_t, l, episode outcome)}，能否估计每个动作 a_t 相对参考策略 π_ref 的“改进程度”，再训练 πθ 在推理时偏向这些改进动作？

这里的关键转化是：不直接优化在线期望回报，而是先训练一个价值函数 V(o, l)，用它给离线数据中的每个时间步计算 advantage，再把 advantage 离散成一个 improvement indicator I。策略训练时不再只学 π(a|o,l)，还学 π(a|I,o,l)。

最重要的思想：RECAP 不是“给好轨迹更大权重”的简单行为克隆。它试图在每个时间步判断：这个动作之后的局部未来是否比当前状态的价值预期更好。也就是说，它关心的是局部改进，而不只是整条轨迹成功与否。
Mathematical objects

2. 数学对象逐个定义：每个变量到底在说什么

符号具体含义工程对应错了会怎样
o_t第 t 步观察，通常包含多视角图像、机器人状态、历史上下文。LeRobot frame 中的 observation 字段。图像/状态错位会让 value model 学到错误时间关系。
a_t第 t 步动作或动作 chunk，π0.5 常涉及连续动作序列。action 或 action horizon。动作与观察不同步会污染 CFG 训练。
l语言指令/task prompt。prompt、instruction、task name。同一任务 prompt 不一致会让 value 条件混乱。
r_t人为定义的稀疏/时间惩罚奖励。成功轨迹每步 -1，终点 0；失败终点如 -300。奖励尺度直接决定 return 分布和正负标签。
G_t从 t 到 episode 结束的折扣累计回报。returns_{tag}.parquet。轨迹边界错会导致 return 跨 episode 泄漏。
V(o_t,l)价值模型预测从当前状态继续执行参考行为的期望回报。SigLIP2 + Gemma3 + Critic Expert。排序不准时，advantage 标签本质是噪声。
A_t动作后 N 步局部未来相对当前价值预期的增益。advantage_continuous。N 太短看不到长期效果，N 太长依赖 bootstrap。
I_t优势是否超过阈值的二值改进指示器。advantage=True/False。阈值错会让“好动作”集合过脏或过窄。
β / guidance推理时放大 conditional 与 unconditional 差异的强度。cfgrl_guidance_scale。太高可能动作激进，太低提升不明显。
Pipeline mechanics

3. 四阶段不是流水账，而是一条误差传播链

1

Compute Returns

把 episode outcome 和时间长度变成每帧监督信号 G_t。

2

Value SFT

训练 V(o,l) 复现归一化 return 的排序和尺度。

3

Compute Advantages

用 N-step return + bootstrap value 计算每帧是否“优于预期”。

4

CFG Training

训练策略同时表示普通分布和高优势条件分布。

这四步的难点在于误差会单向累积：Step 1 的 reward 偏差进入 Step 2；Step 2 的 value 排序误差进入 Step 3；Step 3 的标签噪声进入 Step 4；Step 4 的过强 guidance 又会在真实执行时放大偏差。所以 RECAP 的实操核心不是“跑完四条命令”，而是每一步都要确认中间产物是否有意义。

工程判断：如果 Step 2 的 value model 对 true return 没有可靠排序，后面所有训练都应暂停。继续 CFG 训练只会把策略推向 value model 的错误偏好。
Return design

4. Return 不是标签搬运，而是在定义“任务进展”的坐标系

RLinf 教程里 SFT 成功轨迹使用每步 r_t=-1，终点 r_T=0。当 γ=1 时，越接近成功终点，return 越接近 0；越早的状态 return 越负。这等价于把 value 解释成“离完成任务还差多少时间成本”。

G_t = r_t + γG_{t+1} 成功轨迹，γ = 1： 终点：G_T = 0 终点前 1 步：G_{T-1} = -1 终点前 k 步：G_{T-k} = -k

失败 rollout 则在终止步加入大负奖励，例如 failure_reward=-300。这不是为了精确表示真实物理代价，而是人为拉开失败轨迹与成功轨迹的 return 空间，让 value model 能学会“失败状态或失败前状态不值得模仿”。

为什么输出常归一化到 [-1, 0]

因为成功终点天然是最高价值 0，越差越负。这个范围让 value head 的分类分布稳定，也避免不同数据集 episode 长度和失败惩罚尺度直接冲击训练。

为什么不能只用 success/fail

二值 outcome 只告诉整条轨迹结果，不告诉中间哪一步开始偏离。RECAP 需要 per-timestep advantage，所以必须把 episode 结果展开为每帧 return。

设计选择效果风险应该观察
failure_reward 绝对值很大成功/失败更容易分开。模型只学成败，不学细粒度进展。失败轨迹 value 是否全部塌到下界。
γ=1.0return 等于剩余时间成本，解释简单。长任务早期状态 return 很负，尺度跨度大。不同 episode 长度是否主导 value。
混合 SFT + rollout既有好行为，又有坏行为对比。数据来源策略不同，分布不一致。每个数据集的 return 均值和方差。
Value model

5. Value Model 学的不是“奖励”，而是“在当前观察下未来会有多好”

价值模型的监督目标是归一化后的 G_t。输入是当前观察和语言任务，输出是一个分布式价值预测。使用 201 个 bin 的 categorical distribution，并不是为了形式复杂，而是因为机器人数据的 return 往往多峰、噪声大、尺度不均匀。分布式输出比单个标量更稳定，可以表达不确定性和长尾。

训练数据：x_t = (image_t, language, optional state) 监督目标：y_t = normalize(G_t) ∈ [-1, 0] 模型输出：P(bin_i | x_t), i = 1 ... 201 预测价值：V(x_t) = Σ_i P(bin_i | x_t) * bin_value_i

评估 value model 时，最应该关注的是排序一致性，而不是只看 MSE。因为 Step 3 要用 value 计算 advantage 并按分位数选 top 样本；只要排序错，阈值标签就会错。RLinf 文档强调 eval/spearman_correlation，原因就在这里。

危险信号：训练 loss 下降但 Spearman 很低，说明模型可能只学了数据集均值、episode 长度偏置或视觉捷径，没有学会任务进展。此时继续计算 advantage 没有意义。

视觉难点

价值必须从图像判断物体位置、接触状态、是否偏离任务阶段。失败往往发生在细小接触误差，VLM 未必能捕捉。

语言难点

同样的视觉状态在不同 instruction 下价值不同，例如“拿杯子”和“推杯子”的进展标准不同。

数据难点

如果某些失败模式在数据中很少，value model 不会知道它们危险，advantage 会高估这些状态。

Advantage labeling

6. Advantage 的本质：这个动作后的局部未来，是否超过当前状态的预期

RECAP 的 advantage 不是传统在线 actor-critic 中即时采样的 advantage，而是离线地用 N-step return 和 value bootstrap 拼出来的估计量：

A_t = normalize(Σ_{k=0}^{N-1} γ^k r_{t+k}) + γ^N V(o_{t+N}, l) - V(o_t, l)

逐项解释：

  • normalize(Σ r)：动作之后 N 步真实发生的局部回报。
  • γ^N V(o_{t+N})：N 步之后剩余未来由价值模型估计。
  • - V(o_t)：减去当前状态本来预计的价值，得到“超出预期”的部分。

如果 A_t > 0，可以粗略理解为“这一步之后的发展比 V(o_t) 预期更好”。但 RLinf 实现不是简单用 0 作阈值，而是用分位数，例如 top 30%。这很关键：value 的绝对校准可能不准，但排序相对可用；分位数阈值把问题从绝对判断改成相对筛选。

阈值策略含义优点缺点
A_t > 0只要超过当前预期就正样本。理论直观。依赖 value 绝对校准，实际很脆弱。
Top 30%每批/全局最高 30% 为正样本。对尺度漂移更鲁棒。如果数据整体很差，也会强行选出“相对好”的坏动作。
按任务设阈值每个任务有自己的 improvement threshold。适合多任务。需要更多统计和验证。
Policy extraction

7. CFG 为什么能把 advantage 标签变成策略提升

传统行为克隆学的是 π(a|o,l)：在这个观察和指令下，数据里的人或旧策略做了什么。RECAP 要学的是两个分布：

普通行为分布：πθ(a | o, l) 改进行为分布：πθ(a | I=True, o, l)

训练时，正 advantage 样本带上 improvement indicator，负样本作为 unconditional；同时正样本会以 unconditional_prob 概率丢掉 indicator，让同一个模型既知道普通行为，也知道高优势条件行为。推理时，CFG 使用 conditional 与 unconditional 的差异来偏置动作生成。

直观 CFG 形式： score_guided = score_uncond + s * (score_cond - score_uncond) s = cfgrl_guidance_scale score_cond 表示“高优势条件下应该怎么动” score_uncond 表示“普通数据分布下会怎么动”

这里的 score 可以理解为扩散/flow matching 模型里对动作生成方向的预测。score_cond - score_uncond 就是“高优势条件相比普通行为多出来的方向”。把它放大，就能让策略更像高优势样本。

为什么 guidance 不能无限大：高 guidance 会放大所有差异，包括错误标签、value 偏差和分布外动作趋势。论文语境中也指出，过高 CFG 权重可能把动作推向支持集边缘，表现为激进、不平滑或不安全。
Parameter sensitivity

Hard parts

9. 难点痛点：具体到会卡在哪一步

数据痛点

轨迹质量决定上限

RECAP 不是魔法。如果数据里没有足够多“接近成功但仍有差异”的轨迹，value model 无法学到细粒度进展；如果只有完美演示，缺少失败对比，advantage 标签也缺乏反例。

对齐痛点

frame、action、prompt 必须完全同步

任何一帧错位都会让“这个观察导致这个动作、这个动作导致这个未来”的因果链断掉。RECAP 对时间对齐比普通 SFT 更敏感，因为它要计算 N-step 后果。

价值痛点

Value 学坏了不容易看出来

loss 下降可能只是学到了 episode 长度、场景背景、数据集来源等捷径。必须看 Spearman、分任务统计、视频叠加可视化，而不是只看训练曲线。

标签痛点

Top 30% 不等于好动作

分位数只保证相对高，不保证绝对好。若某个任务数据整体失败，top 30% 可能只是“坏中较好”，CFG 会把这些行为强化。

训练痛点

CFG 学的是差异，不是奖励函数

如果 conditional 和 unconditional 数据分布差异主要来自数据源、场景、相机，而不是动作质量，CFG 会放大这些伪差异。

部署痛点

离线提升需要在线验证闭环

Step 4 的 loss 不能证明策略更好。最终必须在仿真或真实机器人上按 guidance scale 扫描成功率、失败模式和动作安全性。

Diagnostics

10. 最小可用诊断清单：每一步必须看到什么才继续

Step 1 Return
确认 returns_{tag}.parquet 行数等于数据帧数；成功和失败 return 分布有可解释差异；stats.json 包含 return 统计。
Step 2 Value
确认 eval Spearman 为正且逐步提升；预测 value 与真实 return 的散点图不是一团均值；不同任务/数据源没有严重偏置。
Step 3 Advantage
确认 advantage_continuous 分布不是全零或极端单峰；正样本比例接近设定分位数；视频中绿色高优势帧出现在合理阶段。
Step 4 CFG
确认 conditional/unconditional dropout 生效；训练 loss 稳定；不同 guidance scale 下动作从保守到进取连续变化，而不是突然发散。
标签版本
确认 Step 1 data.tag、Step 2 data.tag、Step 3 returns_tag 一致；Step 3 advantage.tag 与 Step 4 data.advantage_tag 一致。
最终评估
至少报告 baseline SFT、RECAP scale=1、RECAP 多个 guidance scale 的成功率、失败类型、平均完成时间和安全异常。
复现实验建议：先用 RLinf 提供的 LIBERO-10 Task 0 数据跑通全链路，不要一开始上真实机器人数据。确认每个 sidecar 文件、tag、value checkpoint、advantage 可视化都正确后，再替换成自己的 LeRobot 数据。
