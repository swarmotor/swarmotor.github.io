OpenPI 微调中混合 LeRobot 数据集的兼容性说明

说明一次微调是否可以使用同属 LeRobot 格式但字段不完全一致的数据，尤其是部分数据带有 episode_metadata、force_torque 等附加字段时，OpenPI 是否会使用这些字段。

1. 结论

一次 OpenPI 微调可以使用多个同属 LeRobot 格式的数据源，也可以让一部分 episode 多带一些附加字段。前提是：

  • 最终进入 OpenPI transform 的核心训练字段必须一致。
  • 核心字段的 shape、dtype、语义必须一致。
  • 额外字段只要没有被 RepackTransform 或自定义 transform 引用，就不会进入模型，也不会参与 loss。

一句话：原始 LeRobot repo 里可以有更多字段，但训练 config 看到并使用的 schema 必须统一。

2. OpenPI 实际读取哪些字段

OpenPI 不是“LeRobot 里有什么字段就都训练”。它由 config 里的 transform 显式取字段。LIBERO 路线会把 LeRobot item repack 成 OpenPI 训练 schema。

典型 LIBERO 风格的 repack 逻辑类似：

_transforms.RepackTransform(
    {
        "observation/image": "image",
        "observation/wrist_image": "wrist_image",
        "observation/state": "state",
        "actions": "actions",
        "prompt": "prompt",
    }
)

因此，模型实际关心的是这些字段：

字段用途必须统一吗
image主视角 RGB 图像是
wrist_image腕部 RGB 图像是
state机器人 proprio/state是
actions动作 chunk / target是
prompt 或 task_index语言任务指令是

3. 额外字段会不会被训练使用

默认不会。如果你的 LeRobot repo 里有这里这些字段，但 config 没有引用它们，它们会被忽略：

episode_metadata
force_torque
camera_intrinsics
segmentation
extra_labels
timestamp
robot_serial

这些字段不会自动进入模型，也不会自动参与 loss。OpenPI 只会沿着当前 DataConfig、RepackTransform、policy transform 和 model transform 明确读取的数据流走。

什么时候会被使用

  • 如果你把 force_torque 拼进 state，它就会被模型当作 state 使用。
  • 如果你在 RepackTransform 里显式引用 force_torque，它就会进入 transform 输出。
  • 如果你写了自定义 transform，把 episode_metadata 转成 prompt 或 state，它就会间接影响训练。
  • 如果你改了 model input spec 或 policy transform 接收新字段，它就可能参与训练。

什么时候可能报错

  • 额外字段本身在 LeRobot 数据集中声明不合法。
  • 同一个 feature 在不同 episode 中 shape 不一致，LeRobot loader 或 batch collate 失败。
  • 你把只在部分数据中存在的字段写进 RepackTransform，另一部分样本没有这个 key。

4. 可以混的数据与不能混的数据

情况能否混说明
一部分 episode 多 episode_metadata可以只要训练 config 不读取它。
一部分 episode 多 force_torque可以只要不拼进 state，不参与训练。
一部分没有 wrist_image不建议直接混需要转换时补齐或统一映射。
一部分 action_dim=7，一部分 action_dim=8不能直接混必须统一 action 维度和语义。
一部分 action 是 delta，一部分是 absolute不能直接混即使 shape 一样，语义不同也会污染训练。
一部分 state 多 force/torque 维度需要处理要么全部 pad/映射到同一 state schema，要么不要放进 state。
prompt 缺失需要补齐可用 default prompt 或 task_index 映射。

5. 推荐的混合方式

不要把不同 schema 的原始数据直接拼在一起训练。建议先创建一个“训练视图 schema”。

必需训练字段：
  image
  wrist_image
  state
  actions
  prompt 或 task_index

可保留但默认不用的额外字段：
  episode_metadata
  force_torque
  depth
  camera_intrinsics
  segmentation
  extra_labels

转换阶段建议

  • 统一图像 key：主视角都映射到 image，腕部都映射到 wrist_image。
  • 统一 state：所有样本输出相同维度、相同含义的 state。
  • 统一 actions：所有样本输出相同 action_dim、相同 horizon、相同动作语义。
  • 统一 prompt：所有样本都能得到语言任务。
  • 额外字段可以保留，但先不要让训练 config 读取。

6. OpenPI config 示例

如果你已经生成了一个本地 mixed LeRobot repo，可以仿照 pi05_libero 加一个 smoke config。

TrainConfig(
    name="pi05_libero_lerobot_mix_smoke",
    model=pi0_config.Pi0Config(pi05=True, action_horizon=10, discrete_state_input=False),
    data=LeRobotLiberoDataConfig(
        repo_id="/absolute/path/to/your_mixed_lerobot_repo",
        base_config=DataConfig(prompt_from_task=True),
        extra_delta_transform=False,
    ),
    batch_size=8,
    weight_loader=weight_loaders.CheckpointWeightLoader("gs://openpi-assets/checkpoints/pi05_base/params"),
    num_train_steps=10,
)

这个 config 仍然只会使用 LIBERO transform 需要的核心字段。额外字段默认不会被读取。

9. 判断额外字段是否被使用

最直接的判断方法：

  1. 搜索 config 里的 RepackTransform 是否引用了该字段。
  2. 搜索自定义 transform 是否读取了该字段。
  3. 检查 batch 输出中是否出现该字段或由它派生的字段。

不会被使用的例子

LeRobot item:
{
  "image": ...,
  "wrist_image": ...,
  "state": ...,
  "actions": ...,
  "prompt": "pick up the cup",
  "episode_metadata": {...},
  "force_torque": [...]
}

RepackTransform 只读取：
  image, wrist_image, state, actions, prompt

结果：
  episode_metadata 和 force_torque 不进入训练。

会被使用的例子

# 转换数据时把 force_torque 拼进 state：
state = concat([joint_position, gripper_position, force_torque])

结果：
  force_torque 已经变成 state 的一部分，会被模型使用。

10. 建议实验顺序

  1. 先让单个 LeRobot 数据源转换成 LIBERO-like schema，并跑 batch smoke。
  2. 再做小比例混合，例如 90% LIBERO + 10% 自有 LeRobot。
  3. 先跑 num_train_steps=10，确认无 shape/dtype/key 错误。
  4. 再跑短训练，观察 loss 是否异常。
  5. 最后才做正式混训。

不要在 action 语义没对齐前混训。 shape 对齐只代表程序能跑，不代表训练语义正确。
