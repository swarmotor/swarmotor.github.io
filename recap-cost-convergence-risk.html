Reality check

RECAP 数据、算量与收敛风险分析

这份报告把一个核心判断展开：RECAP 对数据和算量的要求明显高，而且收敛困难。它不适合被当成“小数据快速增强技巧”，更像是有足够 rollout、GPU、诊断工具和部署闭环之后才值得上的离线 RL 工程管线。

总判断

如果 value model 学不稳，RECAP 后半段全部会变成噪声放大器。 它的风险链条是：数据分布不够好 → return/value 学偏 → advantage 标签脏 → CFG 放大错误方向 → 策略不如干净 SFT。

数据门槛高需要成功、失败、接近成功、多阶段失败和高质量对齐。
算量链条长value SFT、advantage 推理、CFG 训练都不是免费附加项。
收敛脆弱最终效果取决于 value 排序、阈值、guidance 和部署一致性。

Executive verdict

1. 结论先行：RECAP 是重型离线 RL，不是普通微调增强

普通 SFT/LoRA 的目标很直接：让策略模仿数据里的动作。RECAP 多了一层价值评估系统：先判断哪些动作“比预期更好”，再训练策略偏向这些动作。这个设计很强，但也意味着它的成败不只取决于策略模型，还取决于 value model、advantage 标签和 CFG 推理是否全部可靠。

高数据规模要求

没有足够失败和近成功轨迹，优势估计缺乏对比。

高数据质量要求

帧、动作、prompt、outcome 对齐必须严格。

高GPU 预算

value 训练和 advantage 推理会明显增加成本。

高调参复杂度

reward、N、quantile、dropout、scale 互相耦合。

中低小实验性价比

小数据场景常不如把 SFT 和部署校准做好。

关键判断：RECAP 的最小可行前提不是“我有一些轨迹”，而是“我有足够多能训练出可靠 value 排序的轨迹”。如果 eval/spearman_correlation 不稳定或很低，不应该继续做 CFG。
Data burden

2. 数据为什么要求高：RECAP 需要的是“可比较的行为分布”

RECAP 要计算每个时间步的 advantage。它不是只需要成功演示，而是需要知道：同一任务、相近状态下，哪些行为后来成功，哪些行为后来失败，哪些行为更快完成，哪些行为导致偏离。没有这种对比，value model 只能学到粗糙的成败或时间长度。

数据类型为什么需要缺失后果最低检查
成功 SFT 轨迹提供可模仿的高质量动作。策略不知道任务应该怎么完成。成功轨迹覆盖主要任务阶段。
失败 rollout提供负面对比，让 value 知道什么状态危险。value 只会把所有演示都看成好。失败类型不止一种，不只随机崩溃。
接近成功轨迹让 value 学会细粒度进展差异。advantage 只能区分成败，不能指导中间动作。有“差一步成功”的 episode。
多阶段任务轨迹让 value 区分阶段进展。模型可能只学最后阶段，早期动作无信号。每个阶段都有足够样本。
一致 prompt 和 schema让语言条件、视觉状态、动作含义对齐。value 学到数据源或措辞偏差。prompt 风格统一，字段无漂移。
小数据最危险的点：top 30% advantage 总能被选出来，但它不一定是真的好动作。如果数据整体质量差，top 30% 只是“坏里面相对不坏”，CFG 会把这类行为强化。
Compute cost

3. 算量账：RECAP 至少比 SFT 多三笔重成本

普通微调主要消耗在 policy training。RECAP 的消耗是链式的：return 计算便宜，但 value model SFT、全数据 advantage 推理、CFG policy training 都要显存和时间。更麻烦的是，任何前置阶段出错，后面训练都可能白跑。

阶段主要成本为什么贵失败后损失
Step 1 ReturnCPU / IO遍历 LeRobot parquet 和 episode metadata。较低，主要是 tag 和统计重算。
Step 2 Value SFTGPU 训练SigLIP2 + Gemma3 + critic head，多模态输入。高，value 不可靠则 Step 3/4 无意义。
Step 3 AdvantageGPU 推理 + IO要对大量帧跑 value inference，并写 sidecar。中高，阈值可重标，但 value 错要重跑。
Step 4 CFG TrainingGPU 训练π0.5 policy 训练本身就重，还引入 conditional/unconditional。最高，训练完才知道策略是否变好。
Eval / Deployment仿真或真机时间最终必须 rollout 验证，离线 loss 不够。真实机器人时间成本高。
 
总成本不是：一次 policy fine-tune
而是：
  数据清洗
+ return 计算
+ value model 训练
+ value checkpoint 选择
+ advantage 全量推理
+ threshold/quantile 重标
+ CFG policy 训练
+ 多 guidance scale 评估
+ 部署闭环校准
Convergence

4. 为什么难收敛：它有两个模型、三个目标、多个阈值

RECAP 的收敛难不是单一 loss 不下降，而是多个目标不一定朝同一方向变好。value loss 下降不代表排序好；排序好不代表 advantage 标签干净；标签干净不代表 CFG policy 在真实控制中稳定。

Value 层

预测值可能校准差

分类分布 loss 下降，但 Spearman 不高，说明模型可能学均值或捷径。

Advantage 层

阈值制造标签噪声

positive_quantile 过大污染正样本，过小导致样本不足。

Policy 层

CFG 放大错误差异

conditional/unconditional 差异若来自数据源偏差，guidance 会放大伪信号。

典型收敛陷阱：你看到 Step 4 的 policy loss 正常下降，但 rollout 成功率下降。这不是矛盾，因为 policy loss 只说明模型更好地拟合了 advantage 标签，而不是标签本身正确。
Noise amplification

5. 噪声如何被放大：RECAP 是单向误差传播管线

误差来源进入哪里如何放大最终表现
episode outcome 错return错误监督 value。失败轨迹被标成高价值。
图像/action 错帧value 和 policy因果关系断裂。策略学到不对应动作。
value 排序错advantagetop quantile 选错样本。正样本包含坏动作。
阈值过宽CFG trainingconditional 分布变脏。RECAP 与 SFT 差别不清。
guidance 过强推理放大 conditional-unconditional 差分。动作激进、抖动、越界。

因此 RECAP 的正确工作方式应该是“每一步都设停止条件”。如果 Step 2 价值排序没过线，不进入 Step 3；如果 Step 3 可视化不合理，不进入 Step 4；如果 Step 4 仿真 scale 扫描不稳定，不上真机。

Failure symptoms

6. 失败症状：这些现象说明 RECAP 不该继续硬跑

症状说明应该怎么做
Value Spearman 接近 0价值模型没有学到排序。暂停 CFG，检查数据和 reward。
Advantage 分布极端单峰标签没有区分度。调整 failure_reward、N 或重训 value。
正样本集中在少数 episode阈值被数据源或任务偏差主导。按任务/数据集分层统计。
RECAP loss 降但 eval 不升模型拟合标签，但标签无效。回看 advantage 视频，不继续加训。
scale 一提高动作就抖CFG 差分方向不稳定。降低 scale，检查 conditional 数据质量。
Go / no-go criteria

7. 什么时候值得上 RECAP：给一个硬判断标准

值得上

满足这些条件再做

  • 已有稳定 SFT baseline 和部署闭环。
  • 有足够 rollout，且包含成功、失败、近成功。
  • value model 的排序指标稳定为正。
  • advantage 可视化显示高优势帧合理。
  • 有 GPU 预算做多轮 value/threshold/CFG 试验。
不值得上

这些情况先别做

  • 只有几十条成功演示，没有失败 rollout。
  • observation/action schema 还没校准。
  • Isaac 或真机部署还在抽搐阶段。
  • 没有独立 eval 集或 rollout 评估流程。
  • 显存只够勉强微调，无法反复训练 value。
Alternatives

8. 更现实的替代路线：先把便宜收益拿完

路线适合场景优先级原因
高质量 SFT / LoRA小数据、单任务、部署未稳定。最高闭环短，问题容易定位。
数据清洗与重采样轨迹质量参差、prompt/schema 不一致。最高直接改善所有后续训练。
部署校准机械臂抽搐、动作不稳定。最高坐标错时任何 RL 都没意义。
只训练 value 做诊断想评估 RECAP 可行性。中高便于判断是否值得进入 CFG。
RECAP 全流程已有大规模混合数据和算力。最后收益潜力高，但成本和风险也最高。
推荐顺序：SFT baseline → 部署闭环 → 采 rollout → value-only 诊断 → advantage 可视化 → CFG 小规模试验 → scale 扫描 → 真机受控上线。
Checklist

9. RECAP 开工检查表：任何一项不满足都可能白跑

检查项通过标准不通过就做什么
BaselineSFT/LoRA 已有可复现成功率。先训 baseline，不做 RECAP。
数据规模成功、失败、近成功样本都足够。先采 rollout。
数据对齐frame/action/prompt/outcome 无错位。先写数据验证脚本。
Value 指标Spearman 稳定为正，分任务不过度偏置。重看 reward 和数据分布。
Advantage 可视化高优势帧出现在合理动作阶段。调 N、quantile 或重训 value。
算力预算能承受至少 2-3 轮 value/CFG 试错。降级为 SFT 或 value-only。
部署验证仿真/真机能稳定执行 baseline。先修 observation/action adapter。

结论：你的判断“RECAP 对数据与算量要求明显高，而且难收敛”不是保守，而是实际工程里最应该先写在白板上的风险。RECAP 值得研究，但不应该在基础 SFT、数据闭环和部署校准尚未稳定前作为主路线。
