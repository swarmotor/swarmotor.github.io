Research Report · SOTA Rollout + VLM Eval

自动评测应从“看完视频判成败”升级为混合式评测系统

面向 OpenPI / Isaac Sim / 真实机器人 rollout，本方案建议采用硬规则、子目标向量、VLM 证据判断、pairwise 排名和人工校准闭环。核心目标不是替代所有人工，而是把人工从逐条看视频转移到标注校准集、复核低置信样本和审查评测偏差。

主指标：Subgoal Vector 评测对象：视频 / 多相机帧 / 状态事件 适配：OpenPI、Isaac Sim、DROID 风格数据 输出：HTML 报告 + JSON 结果
结论 不要用单一 VLM 二分类成功率作为最终评测。
MVP 优先级 先评测已有真实/仿真 rollout，再做 world-model rollout。
质量闸门 规则信号优先；VLM 只负责视觉语义与模糊子目标。
Executive Decision

推荐方案：RolloutVLM-Eval

构建一个“后验自动评测”框架：记录 rollout 后，用任务规格和硬规则先提取确定性信号，再让 VLM 对可见子目标、失败原因和安全风险做结构化判断。最终输出每个 episode 的子目标成功向量、进度分、失败分类、证据帧和置信度；对多策略比较则使用 pairwise A/B + Bradley-Terry 或 Elo 聚合排名。

SOTA Signals

已核验的关键项目与可借鉴点

来源 核心贡献 对本项目的启发
StepEval 用 VLM 对机器人操作轨迹做子目标级评测，主产物是 per-subgoal success vector。 把整体成功率降级为聚合指标，核心报告每一步做成/没做成。
WorldEval 用 world model 生成 action-conditioned robot video，在线替代部分真实评测。 二期方向：用视频世界模型扩大 policy 评测规模，但不应作为 MVP 起点。
RoboArena 分布式真实机器人双盲 A/B policy 比较，基于 progress score 和 preference 聚合排名。 多策略比较不要只看平均成功率；引入 pairwise ranking 和任务难度建模。
OSWorld 真实电脑环境任务具备 setup、执行过程记录和 execution-based evaluator。 每个任务应自带可复现初始化和可执行硬评测脚本。
AndroidWorld 116 个 Android 任务、动态参数化、durable reward signals。 任务随机化和稳定 reward signal 可迁移到 Isaac Sim 场景扰动。
WorkArena BrowserGym 生态下的企业工作流 benchmark，每个任务有 validate 逻辑。 机器人任务也应把 oracle/validator 作为任务定义的一部分。
VLMEvalKit / OpenCompass 成熟的模型适配、并发评测、缓存、LLM judge 和 cascade evaluator 基础设施。 复用其“模型统一接口 + evaluator 可插拔 + 结果可复现”的工程模式。
WFM-Eval 指出 holistic VLM judge 在机器人视频评测中存在偏置，应拆分 task completion、object hallucination、temporal consistency。 本项目必须多维诊断，禁止把 VLM 的单个整体分数当作最终真值。
System Architecture

六段式评测流水线

系统以 rollout artifact 为中心，不侵入 policy 本身。每个模块输出结构化数据，方便缓存、复跑、审计和模型替换。

1. Recorder采集视频、关键帧、动作、状态、事件、policy metadata。
2. Task Spec定义 subgoals、硬规则、可见证据、失败模式和安全约束。
3. Hard Eval先跑状态/仿真/脚本验证，生成确定性标签。
4. Sampler按事件、动作阶段和视觉变化抽取多视角帧或短片段。
5. VLM Judge按 rubric 输出 JSON：子目标、置信度、证据帧、失败原因。
6. Ranker聚合报告，生成 policy 对比、A/B 排名和低置信复核队列。
Data Contract

推荐数据格式

Episode Artifact

  • metadata.json：policy、checkpoint、task、seed、环境版本、相机配置。
  • events.json：仿真事件、接触、碰撞、目标状态、timeout。
  • actions.parquet：时间戳、动作、控制模式、推理延迟。
  • videos/*.mp4 与 frames/：外部相机、腕部相机、可选深度图。

Task Spec

  • instruction：自然语言任务。
  • subgoals：有序步骤、成功条件、必要证据。
  • hard_checks：可执行 evaluator 或仿真状态条件。
  • vlm_rubric：评分尺度、反例、不可见时返回 unknown。
Metrics

最小指标集

主评测

overall success rate、subgoal success rate、progress score 0-5、time-to-completion。

失败诊断

failure taxonomy、object missing/wrong-object、temporal inconsistency、safety violation。

裁判质量

VLM-human agreement、hard-VLM disagreement、judge confidence、multi-judge agreement。

Judge Design

VLM Judge 设计原则

必须做

  • 用 JSON schema 限制输出，不让模型自由写作文。
  • 每个判断必须引用证据帧或短片段时间戳。
  • 允许 unknown，不可见或证据不足时不能强判。
  • 对同一任务维护少量人工 gold label，定期校准 prompt 和模型。
  • 对低置信、高影响、规则冲突样本进入人工复核池。

必须避免

  • 避免单 prompt、单模型、单分数作为最终真值。
  • 避免只给完整视频，长视频容易丢关键动作和时序细节。
  • 避免把 VLM 视觉幻觉当作物理事实。
  • 避免用 prompt 调参直接追 leaderboard，而不看人工一致性。
  • 避免忽略相机盲区；看不到就应返回 unknown。
Implementation Roadmap

六周 MVP 路线

第 1 周：定义协议

完成 rollout artifact 目录、task.yaml 模板、评测结果 JSON schema。接入 OpenPI remote policy 与 Isaac Sim 记录器。

第 2 周：硬评测优先

实现 3-5 个任务的 hard evaluator：目标位姿、抓取状态、放置区域、碰撞、timeout、路径越界。

第 3 周：VLM Judge

实现关键帧采样、多视角输入、JSON judge prompt、成本/延迟记录、结果缓存。

第 4 周：校准集

每个任务采集约 20 条 rollout，人工标注 100-300 个子目标样本，统计 VLM-human agreement。

第 5 周：报告与复核

生成 HTML/JSON 报告、失败热力图、证据帧索引、低置信复核队列。

第 6 周：策略比较

加入 pairwise A/B 评测和 Bradley-Terry/Elo 排名，输出 policy rank、置信区间和任务簇表现。

Risk Register

主要风险与缓解

VLM 偏置

用多模型一致性、人工校准集和硬规则冲突检测缓解；不要把单模型结果称为 ground truth。

相机不可见

任务规格中写明必要证据和推荐相机；证据不足时返回 unknown，进入复核而非强判失败。

仿真与真实差异

仿真 hard checks 只作为可验证信号；真实视频仍需 VLM/人工校准。

评测被 prompt 过拟合

固定隐藏校准集，分离开发集和验收集，记录每次 prompt/model 版本。

Recommended Stack

建议技术栈

评测运行

Python + uv，任务 evaluator 用可插拔 Python module；并发用 Ray、Celery 或简单进程池。

数据存储

本地 artifact + JSON/Parquet；后续可接 S3/MinIO，报告索引进 SQLite 或 DuckDB。

模型接入

API judge 用 GPT-4o/Gemini/Claude；本地 judge 用 Qwen-VL、InternVL、Kimi-VL、GLM-V。

Final Recommendation

先做“可信自动评测”，再做“自动生成评测环境”

短期最值得做的是把现有真实/Isaac Sim rollout 评得更细、更稳、更可复核。WorldEval/RoboWorld 这类世界模型评测很有潜力，但它们引入新的模型误差源，适合作为二期扩展：当基础评测框架、校准集和报告体系稳定后，再用 world model 扩大覆盖和做安全预筛。
