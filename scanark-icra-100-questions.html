Part I

一、论文定位与立意

01Scan2VLA 是什么？这篇论文要解决什么问题？

Scan2VLA 是一个与目标本体无关的适配框架：把一次联合优化的原生 3DGS 场景转化为交互式 Gaussian 数字孪生，再把通用 VLA 基模适配到预训练中完全没有出现过的机器人本体（AgiBot G2）。

要解决的问题：新本体适配需要覆盖新相机、本体状态和动作语义的真实演示，采集成本高；而仿真数据常因「静态背景 + 独立物体拼接」在物体边界与接触区域引入外观差异，导致数据价值下降。

02「scene-native」（场景原生）指什么？

指交互物体不是外部扫描后插入场景的独立资产，而是直接从它实际使用的同一场景、同一坐标系、同一采集条件下恢复的原生 Gaussian。物体与背景共享采集域，避免第二次外观对齐，策略观测更匹配部署环境。

03本文定位为什么「不是又一个 Gaussian 仿真器」？

因为「3DGS 仿真能否训练 VLA」已不再足以构成新意：SplatSim、GSWorld、GS-Playground 推进了平台与吞吐，LEGS、Mirage2Matter 已用 Gaussian 世界生成 VLA 数据。本文研究的是更窄、可检验的问题——通用 VLA 基模能否通过交互式 Gaussian 数字孪生适配到一个真正未见的新本体，以及 scene-native 资产来源是否改变训练数据价值。

04「零真实演示」指什么、不指什么？

仅指 VLA 后训练适配数据不需要真实 G2 演示。不排除：构建数字孪生所需的真实场景采集、机器人模型、G2 标定、动作接口与低层控制器——这些组件在所有条件下冻结，且不宣称由 Scan2VLA 学得。

05为什么实证结论只限定 AgiBot G2？

G2 是唯一真实部署本体。本文 formulation 是 embodiment-agnostic（与本体无关），但「通用性」不等于多本体实证。正文主张限定为「在一个真正未见的目标本体上验证通用适配框架」，不宣称覆盖所有机器人。

06为什么「3DGS 仿真能否训练 VLA」不再足以构成立意？

SplatSim 已展示零样本迁移，GSWorld / GS-Playground 提供闭环评测与高吞吐学习，LEGS 与 Mirage2Matter 已用 Gaussian 世界生成 VLA 数据。因此立意必须落到资产来源：scene-native 提取是否提高未见本体适配的数据价值。

07核心洞见是什么？

交互物体不应作为外部资产插入，而应直接从其实际使用的目标场景中恢复。只做一次原生 3DGS 重建，自动赋予实例身份，把物体提取为可独立运动的 Gaussian 子集，再补全、绑定物理、生成轨迹，最后把通用 VLA 基模适配到目标本体的相机、状态与动作接口。

08为什么物体要从目标场景原位提取而不是外部插入？

外部插入需要独立扫描 / 生成 + 跨域对齐，会在物体边界、接触区与遮挡区域引入外观 / 坐标系差异；原位提取让物体与背景共享采集域，直接得到与部署观测更一致的渲染。这正是「场景原生资产比独立插入资产提供更匹配策略观测」这一主张的来源。

09本文三条主要贡献是什么？
  1. 场景原生分解：在联合优化的原生 3DGS 场景中自动分离背景、机器人与交互物体，避免人工裁剪与独立物体重建。
  2. 可仿真资产生成：补全被遮挡的物体与背景区域，生成与 Gaussian 对齐的闭合碰撞几何（物性估计来自已有工作，非本文贡献）。
  3. 通用基模到未见本体的适配：在 π0.5 与 SmolVLA 上检验零真实 G2 演示的适配，用 sim-real correlation 与真实数据学习曲线量化可靠性与演示节省。
10标题为什么最终推荐 Scene-Native Vision-Language-Action Learning with Interactive Gaussian Digital Twins？

它直接点出最可区分的方法机制（scene-native），并保留 VLA 真实数据效率这一实验终点；相比「Interactive Gaussian Digital Twins」类标题，避免与 High-Fidelity Digital Twin、GaussTwin、ArtiTwinSplat 正面同类化。「数字孪生」的系统感有所减弱，但换来定位清晰、可防守。

Part II

二、背景与动机

11通用 VLA 基模适配新机器人本体，难在哪？

需要覆盖新相机、本体状态、动作空间与任务的示范数据；这类数据依赖真实机器人本体、人工遥操作、物理复位与安全监督，成本高且难以扩展。

12为什么真实演示数据采集成本高？

每条轨迹都要真实机器人本体 + 人工遥操作 + 失败后的物理复位 + 安全监督；任务、物体一变就要重采，规模上不去。

13仿真数据的主要问题是什么？

当渲染观测与部署相机域不匹配时，仿真数据对真实策略的价值显著下降；尤其在操作物体边界与接触区域，静态背景与独立交互物体的拼接会引入外观差异。

14为什么「静态背景 + 独立交互物体」的拼接会引入外观差异？

独立物体资产与背景来自不同采集 / 生成域，光照、材质、分辨率不一致，拼接后边界与接触区出现明显接缝；scene-native 资产与背景同域渲染，边界一致。

153DGS 是什么？为什么适合与物理引擎结合？

3D Gaussian Splatting 用显式 Gaussian 原语做实时新视角渲染，重建质量高、渲染快，能提供照片级观测；显式几何结构便于与物理引擎绑定，从而生成闭环仿真训练数据。

16SplatSim、Re3Sim、GSWorld、GS-Playground 各做了什么？

SplatSim 首次展示 Gaussian 渲染的 RGB 操作策略零样本迁移；Re3Sim 将照片级场景与域随机化、混合资产结合；GSWorld 提出 GSDF 资产格式与覆盖训练 / 评测 / DAgger 的闭环套件；GS-Playground 把批量 Gaussian 渲染与刚体物理扩展到大规模视觉强化学习。这些工作主要推进平台能力、吞吐或下游迁移。

17LEGS 与 Mirage2Matter 已做了什么？缺口在哪？

LEGS 用 3DGS 背景 + Mesh 前景微调无需遥操作的人形 VLA；Mirage2Matter 分别重建场景与物体、对齐碰撞 Mesh 生成 VLA 数据。它们的动态前景仍来自独立扫描 / 生成或跨表示对齐，没有回答「同一场景原位提取的物体 Gaussian 是否提高未见本体适配的数据价值」。

18本文「主张—机制—证据」矩阵是什么？
  1. 一次联合重建可生成有效可移动资产 → 机制：实例分解 + 双向补全 + 碰撞绑定 → 证据：Mask / 边界、补全、Chamfer、闭合率、碰撞误检与失败案例。
  2. scene-native 资产提供更匹配的观测 → 证据：配对状态渲染的 LPIPS / DINO / 边界误差，按 observed / synthesized 分层。
  3. 通用基模可适配未见 G2 → 证据：基模 manifest 审计、零真实演示锚点、真实数据学习曲线。

原则：证据不足就缩小主张，而不是增加形容词。

19本文如何与 High-Fidelity Digital Twin、GaussTwin、ArtiTwinSplat 区分？
  • High-Fidelity Digital Twin：从场景 3DGS 提取语义与碰撞 Mesh 用于规划与真机执行——资产侧最接近，本文需强调「可移动原生 Gaussian + 双向补全 + VLA 学习曲线」。
  • GaussTwin：在线物理预测—视觉校正（状态同步），不是离线场景资产分解。
  • ArtiTwinSplat：依赖观察到的关节运动恢复刚性部件；本文从一次静态联合重建提取可自由移动的刚体，不依赖关节观测。
20最需要防守的先验工作是哪几个？如何防守？

方法侧 High-Fidelity Digital Twin，应用侧 LEGS 与 Mirage2Matter，系统侧 GSWorld 与 GS-Playground。防守方式：用受控资产来源（Independent-GS 对照）与未见 G2 基模适配证据，证明 Scan2VLA 不是这些系统的轻量组合。

Part III

三、方法：场景原生数字孪生与机器人适配

注：方法部分与其他 VLA 论文一致，重点讲机器人问题——新本体适配需要什么样的数据源、scene-native 资产如何服务观测 / 状态 / 动作接口、轨迹如何生成与后训练。3DGS 的获得与处理（重建、分解、补全、碰撞）不是本文重点，仅注明要点并参照参考文献（Kerbl et al. 2023；High-Fidelity Digital Twin；Mirage2Matter 等）。

21Scan2VLA 系统流程分哪几步？
  1. 真实场景采集（同一相机、曝光和部署环境）；
  2. 原生 3DGS：一次联合场景优化；
  3. 实例级分解：背景、机器人与交互物体；
  4. 仿真数据：完整几何、物理绑定与轨迹；
  5. 真实部署：VLA 后训练与真实成功率。

这条管道从场景直达机器人策略，是机器人数据与适配的主线；模块构成见 Q26。

22为什么用「交互式 Gaussian 数字孪生」来解决新本体适配？

从机器人视角看：VLA 适配新本体需要覆盖新相机、本体状态与动作接口的闭环数据源——既要有照片级观测，又要能反复生成可交互轨迹。交互式 Gaussian 数字孪生恰好提供这两点；而 scene-native 保证资产与部署观测同域。3DGS 只是实现这个数据源的载体，重建本身的细节不是本文重点。

23scene-native 资产从机器人视角解决了什么？

三个层面：① 相机域一致——渲染观测与部署相机同域，减少 sim2real 视觉落差；② 接触 / 边界区一致——物体边缘与遮挡区域不出现拼接接缝，抓取与放置更可靠；③ 轨迹坐标系一致——物体、机器人与场景在同一坐标系下生成状态—动作序列，直接服务于策略训练。

24真实演示节省率如何定义（公式 3）？为什么用它？

Saving(τ) = 1 − Nreal_Scan2VLA(τ) / Nreal_RealOnly(τ)，即达到同一目标真实成功率 τ 时，Scan2VLA 方案所需真实演示数与纯真实数据方案之比。它把「真实数据效率」与「某个基模能达到的最高绝对分数」区分开，跨条件可比。

25场景如何表示成机器人可用的可交互资产？

用统一符号简注（公式 1–2）：场景 Gaussian 集合 Gscene = Gbg ∪ Grobot ∪ ⋃k Gobj_k 分为背景、机器人与物体；第 k 个物体资产 Ak = (Gobj_k, Mk, Pk) 由物体 Gaussian 子集、闭合碰撞 Mesh 与物性参数构成，供模拟器与轨迹生成使用。统一符号供后续模块与实验引用；分解、补全与碰撞的详细实现见 Part IV 与参考文献，非本文重点。

26系统由哪些模块构成？各自职责是什么？

模块 A 场景重建（一次联合优化，不对单个物体重新扫描）→ B 实例分解 → C 双向补全 → D 物理资产（碰撞绑定）→ E VLA 数据生成与后训练。A–D 负责「把场景变成机器人可用的资产」（实现细节见 Part IV，非本文重点）；E 面向机器人本体适配，生成相机观测、状态与动作序列。

27扫描时机器人是否在场？坐标系如何对齐？

待填写（正文要求交代）。关键点：扫描时的场景、机器人与模拟器三套坐标系必须对齐，否则生成的轨迹与部署观测会错位；这是场景重建阶段必须披露的实现细节。

28物体移动时数字孪生如何生成动态观测？

物体 Gaussian 按刚体变换随姿态更新（公式 4：μi^t = R_t^k μi^0 + t_t^k、Σi^t = R_t^k Σi^0 (R_t^k)ᵀ），从而渲染出抓取、搬运过程中的连续观测序列。边界：保留的是采集条件下的辐射外观，不执行物理正确的动态重光照。

29孪生渲染的物理边界对机器人训练有什么影响？

烘焙阴影 / 高光不随物体移动更新，大幅移动时可能暴露生成表面或保留不真实光照——策略可能学到错误的视觉线索。本文以 observed / synthesized 分层统计与失败案例量化该边界（见局限章节），不展开渲染实现。

30资产与模拟器如何绑定？物性参数从哪来？

资产（视觉 Gaussian + 碰撞 Mesh）与模拟器绑定后，按目标本体的相机、状态与动作接口生成数据。质量、摩擦、质心、惯性等物性参数由单独的已有物性估计工作（如 Scalable Real2Sim）提供，本文作为固定输入，不重复宣称为贡献。

Part IV

四、资产获得：实例化 3DGS 与补全（简注）

注：本节说明「资产如何获得」——但这不是本文重点；本文重点是这些资产的机器人适配价值（见第三、五部分）。此处仅注明要点，详细实现参照类似参考文献：3DGS 原语见 Kerbl et al. (2023)；多视角语义融合、去噪与碰撞 Mesh 见 High-Fidelity Digital Twin（Sun et al., 2026）；场景 / 物体重建与补全对齐见 Mirage2Matter（Gao et al., 2026）；物性估计见 Scalable Real2Sim（Pfaff et al., 2025）。

31对象的实例化 3DGS 如何实现？

模块 B「实例级 Gaussian 分解」：将多视角 2D 实例证据融合到 Gaussian 原语，为每个 Gaussian 预测背景 / 机器人 / 物体标签，清理边界泄漏，输出 Gobj_k 与 Gbg。实现细节参照类似工作：多视角语义融合见 High-Fidelity Digital Twin（Sun et al., 2026）。

32实例标签如何从多视角证据融合到 Gaussian 原语？

各视角 2D 实例 Mask 经投影映射到对应 Gaussian 后跨视角融合，为每个 Gaussian 给出单一标签。实现参照 High-Fidelity Digital Twin（Sun et al., 2026）的多视角语义融合。

33边界泄漏如何清理？

按置信度过滤、边缘再分配或几何一致性校验，保证 Gobj_k 与 Gbg 边界干净。实现参照类似实例分割后处理工作，不展开。

34实例分解输出是什么？

Gobj_k、Gbg 与物体规范坐标系，作为补全、碰撞绑定与轨迹生成的输入。仅此注明。

35为什么要物体补全？补哪些区域？

旋转会暴露底部与遮挡表面，需视觉 + 几何补全。实现参照 High-Fidelity Digital Twin（Sun et al., 2026）与 Mirage2Matter（Gao et al., 2026）的补全 / 重建流程。

36为什么要背景补全？补哪些区域？

移走物体暴露背景空洞，需补全并消除残影。实现参照类似背景修复 / 补全工作（同 Q35 文献），不展开。

37如何标记真实观测 Gaussian 与生成 Gaussian？为什么？

记录观测 / 生成来源，供「真实观测区域 / 补全区域」分层统计与消融使用。仅此注明。

38碰撞 Mesh 如何生成？

表面提取 → 去噪 → 修补 → watertight → 简化 → 碰撞分解，并量化与 Gaussian 的对齐误差。流程参照 High-Fidelity Digital Twin（Sun et al., 2026）的碰撞 Mesh 构建。

39如何量化 Gaussian 资产与碰撞 Mesh 的对齐误差？

碰撞 FP/FN 率、位姿对齐误差与 Chamfer distance。指标定义参照类似 Real2Sim 评测工作，不展开。

40物体底部 / 遮挡面如何完成视觉与几何补全？

利用可观察部分先验生成未观察表面（视觉 + 几何）。实现参照类似补全文献（同 Q35），补全区域需显式标记以便分层评测。

41补全后如何消除移走物体暴露的背景残影？

利用多视角信息推断被遮挡背景并重填充，消除残影；以残影、空洞与重建误差评测。实现参照类似背景补全工作，不展开。

42为什么本文不把物性估计作为贡献？

物性参数由已有工作提供（如 Scalable Real2Sim，Pfaff et al., 2025），作为固定输入，不重复宣称为贡献。

43阴影与高光被烘焙在表示中会带来什么问题？

烘焙阴影 / 高光不随物体移动更新，大姿态变化下渲染不真实；以 observed / synthesized 分层与失败案例量化。仅此注明。

44透明、反光、细薄、严重遮挡物体为什么困难？

3DGS 以不透明度 / 外观系数建模表面，此类物体收敛与补全困难。作为已知局限列出，不展开。

45实例分割误差如何向下游传播？

标签错误 → 补全错误 → 碰撞变形 → 数据带噪 → 策略边界出错；正文以「分解 → 补全 → 碰撞 → 策略」链式证据逐级验证。仅此注明。

Part V

五、方法：VLA 数据生成与后训练

46VLA 训练数据如何生成？轨迹来自哪里？

在绑定好的数字孪生中，按目标本体接口生成图像、语言、机器人状态与动作序列。专家轨迹来源待填写（运动规划、仿真遥操作或脚本控制器）；所有视觉基线共享相同的状态—动作轨迹。

47每条数据包含什么？

同步相机观测、机器人状态、语言指令与动作块（action chunk）。

48为什么所有视觉基线共享轨迹、动作空间、归一化、增强、优化预算与 checkpoint 选择规则？

保证对比公平：唯一变量是资产来源（背景 + 物体表示），其余全部冻结；否则无法把性能差异归因于 scene-native 资产。

49如何审计 π0.5 与 SmolVLA 预训练数据中不含 G2？

在施加任何实验处理前，审计 checkpoint hash、预训练 / 适配数据 manifest 与 cutoff 版本，确认其中没有 G2 的图像、本体状态、动作或机器人演示。该声明只针对「基模预训练 + 策略适配数据」，不排除共享且冻结的 G2 标定等信息。

50为什么还要披露 VLA 之外的 G2 信息？

G2 标定、URDF / 几何、动作适配器与低层控制器训练也用了真实 G2 信息。必须披露，避免读者误以为「零真实演示 = 零 G2 信息」；这些组件冻结且不宣称由 Scan2VLA 学得。

51Base zero-shot 是什么？为什么不执行优化？

用预训练 checkpoint 直接部署到 G2 的对照条件：不做任何后训练，与后训练条件共享同一基模 checkpoint 架构与冻结执行接口。它回答「基模先验本身在未见 G2 上能走多远」。

52后训练用什么算力？部署用什么？

后训练用 NVIDIA RTX A6000；部署推理用 NVIDIA RTX 5060；真机为 AgiBot G2。论文需补充推理机机载 / 外置、CPU / 内存、CUDA / 框架版本、通信接口、控制频率与 mean/P95 观测—动作延迟。

53「冻结 G2 低层控制器」意味着什么？

低层控制器、动作接口、移动—操作控制栈在所有条件下不变，由 Scan2VLA 之外提供。意味着实验衡量的是 VLA 策略层适配，而不是控制器学习；这隔离了「通用基模先验」与「新本体适配」两个因素。

54本文为什么不宣称学得了执行控制？

执行仍依赖 G2 标定、机器人模型、动作接口与低层控制器——这些是冻结的既有组件；Scan2VLA 贡献的是数据与策略适配流程，不是控制栈。防止把系统级结果误报为学习贡献。

55为什么说 formulation 面向一般本体，但实证只覆盖 G2？

公式 (1)–(6)、模块流程与接口抽象都不绑定具体机器人，故称 embodiment-agnostic；但真机证据只有 AgiBot G2，结论边界写明「在一个真正未见的目标本体上验证通用适配框架」，不宣称多本体实证。

Part VI

六、实验设计：任务与基线

56四个研究问题 RQ1–RQ4 是什么？
  • RQ1：自动场景分解与双向补全能否生成准确、可碰撞的物体与背景资产？
  • RQ2：保留可移动物体的 scene-native 外观能否提高配对 sim-real 视觉一致性，且仿真策略表现能否预测真实表现？
  • RQ3：仿真生成轨迹能否在零真实演示下把预训练完全不含 G2 的通用基模适配到 G2？节省多少真实演示？
  • RQ4：效应能否从短任务延伸到长程任务并承受误差累积？哪些组件与场景变化驱动增益，场景原生假设在哪失效？
57实验章节为什么按「先资产、后策略」组织？

因果顺序：先证明资产成立（分解 / 补全 / 碰撞证据，回答 RQ1），再证明策略受益（RQ2–RQ4）。资产质量不过关，后面的策略结论就没有基础；这样组织也让审稿人按证据链逐级核查。

58短任务是什么？它起什么作用？

短程诊断任务：G2 从桌面抓取一个饮料瓶放入野餐篮（正确瓶稳定抬起、释放在目标体积内、保持 T 秒，且无人工干预 / 超时 / 碰撞 / 掉落 / 安全中止）。作用：隔离基础抓取—放置能力，不与主任务同等支撑长程结论。

59主要长程任务是什么？分哪几个阶段？

全身长程野餐收纳：从摆零食物品的桌面开始，识别并逐件抓取目标零食 → 全部装入野餐篮 → 全身协调端起并搬运已装载篮子 → 稳定放入汽车后备箱。分 P1 选择 / 抓取、P2 装篮、P3 全身端起 / 搬运、P4 后备箱放置四个累计阶段。

60四个阶段各是什么？典型失败？
  • P1 选择 / 抓取：正确物体稳定抓起并离开桌面；失败：错选、抓空、滑落、禁区碰撞。
  • P2 装篮：所有指定零食在篮子目标体积内；失败：漏装、篮外放置、已装物掉出。
  • P3 全身端起 / 搬运：篮子与内容物在搬运中稳定；失败：倾覆、掉出、失衡、安全停止。
  • P4 后备箱放置：篮子完全进入目标区并稳定保持 T 秒；失败：部分越界、不稳定、碰撞、超时、人工干预。
61E2E 成功如何定义？

全部指定零食最终仍在野餐篮内 + 篮子达到后备箱内预设稳定姿态 + 全程无人工干预、超时、禁止碰撞、零食 / 篮子掉落或安全中止。需预先填写零食集合与数量、初始位姿分布、目标体积、稳定容差、保持时间与总时限。

62为什么 E2E 成功率不能单独代表执行质量？

两个方法可能得到相同的二元成功，但抓取次数、掉落数、篮子稳定性、放置精度完全不同。因此主终点（E2E）之外还记录连续过程指标：完成度、每件抓取尝试、篮子 roll/pitch 与内容物保持率、后备箱位姿误差、任务时长与安全事件。

63长程任务有哪些关键过程指标？
  • 任务完成度：Citem = Nin-basket / K、累计阶段数、最长连续完成阶段、首个失败阶段。
  • 识别与抓取：正确率、每件尝试数、重抓 / 错抓 / 掉落、稳定抬升时间。
  • 装篮质量：篮内比例、中心误差、包含余量、碰撞次数、每件放置时间。
  • 搬运稳定性：抬升高度、roll/pitch 峰值与 RMS、内容物保持率、搬运距离 / 时间、跟踪误差。
  • 后备箱放置：最终位姿误差、包含余量、稳定保持时间。
64表 1 的基线条件如何设计？各回答什么问题？

所有仿真条件共享轨迹、相机、碰撞几何、物理参数、帧数与初始状态分布，只变「背景 + 物体外观来源」：Base zero-shot（预训练基模直接部署）、Real-only（真实学习曲线）、Scan2VLA-only（原生场景原位提取）、Independent-GS-only（单独重建后插入）、GS-BG + Mesh-Obj-only（原生背景 + Mesh 前景）、Mesh/PBR-only（传统网格），以及对应 +Real 组合（演示节省率 / 学习曲线）与 Single-Scene（场景多样性的作用）。

65Independent-GS 如何构造才能公平？

使用同一个物体与目标场景，但先单独扫描物体再完成插入；必须获得与 Scan2VLA 相同的碰撞 Mesh、对齐流程、颜色校准投入、相机模型与人工处理预算。它是受控的「独立资产来源」基线，不宣称端到端复现 GSWorld / Mirage2Matter。

66Mesh/PBR 基线为什么要做合理校准，不能故意设弱？

若把传统仿真基线故意设弱，得到的提升没有说服力。Mesh/PBR 必须进行合理的相机、材质与灯光校准；所有 only 条件使用相同的仿真轨迹数量与后训练预算，保证提升来自资产来源而非投入差异。

67「18 个模型、54 个验证单元、216 条真实数据」怎么来的？

3 个任务 × 3 个场景 × 2 个 VLA 基模 = 18 个「任务—场景—基模」模型，每个模型只执行其对应任务；每模型 3 个独立验证组 × 每组 4 个真实初始状态 = 54 个验证单元、216 条真实评测数据（每模型 12 条）。

68为什么验证组不是训练种子？

3 个验证组是评测结构，不是训练随机种子；训练种子若重复，应作为另一个独立实验因素，不能称为验证组。这避免把「同一随机性的多次运行」误当独立证据。

69Sim-real correlation 如何避免 864 条仿真开销？

在查看仿真结果之前，从 216 条真实数据中按任务、场景、基模、验证组分层预注册抽取配对子集 𝒫（Npair 条），只在仿真中重放这些完全相同的 seed；仿真开销是 Npair 而不是默认追加 864 条。正式评测前固定 Npair、18 个模型 / 54 组间的分配与抽样 seed。

70为什么 54 个验证单元不能当作 54 个独立样本？CI 如何算？

54 个验证单元嵌套在 18 个模型内（每模型 3 组），同模型内高度相关，不能当完全独立点。置信区间以模型为 cluster bootstrap，每次抽样保留该模型的验证组结构；不能对单个模型仅有的 3 个验证点单独算相关系数，也不能事后挑选「更相关」子集。

Part VII

七、评估：一致性、效率与统计

71资产重建质量用什么指标？
  • 实例分解：Mask mIoU、Boundary F-score、Gaussian leakage rate；
  • 背景补全：物体移除后的残影、空洞与重建误差；
  • 物体几何：Chamfer distance、体积误差、闭合 Mesh 成功率；
  • 碰撞一致性：碰撞 false-positive / false-negative 与位姿对齐误差。

图 3 要求主动展示边界泄漏、残影、生成区域与失败案例，而不是只展示成功样例。

72光度一致性如何评测与分层？

在仿真与真实环境重放配对状态与相机位姿，比较 Scan2VLA、Independent-GS、GS-BG + Mesh-Obj、Mesh/PBR 的 LPIPS、DINO 特征距离与物体边界区域误差；按「真实观测区域 / 补全区域 / 相对扫描姿态的移动幅度」分层统计。

73策略层 sim-real correlation 用什么指标（公式 5）？

对每个模型 m：p̂real,pair_m = (1/nm) Σ_{i∈𝒫m} yreal_i、p̂sim,pair_m = (1/nm) Σ_{i∈𝒫m} ysim_i，形成 18 个模型级仿真—真实表现对；报告 Spearman ρ、Pearson r 与 mean absolute calibration error，画紧凑散点 / 校准图。

74逐 episode 一致性 2×2 表是什么？

对 Npair 条完全相同的 seeds，统计 both-success、sim-only-success、real-only-success、both-failure 四格，报告 agreement rate；完整逐 episode ledger 与 Matthews correlation coefficient 放补充材料。

75真实数据学习曲线如何画（公式 6）？

对每个基模训练 Real-only 与 Scan2VLA + Real 两条曲线：Nreal ∈ {0, 5, 10, 25, 50}，Nsim = 500 / 任务。横轴为目标任务真实演示数量，纵轴为真实机器人成功率及 95% CI；图含零真实演示锚点（Base zero-shot 与四种 only 条件）与主要曲线（Real-only、Scan2VLA + Real、Independent-GS + Real、Mesh/PBR + Real）。

76为什么选择两种不同的 VLA base model？为什么绝对成功率不直接比较？

选 π0.5 与 SmolVLA，理由包括正文依据与合理补全：

  1. 检验适配框架与基模无关：若两种模型都能从「零真实演示 + Scan2VLA 数据」受益，结论就不是某个模型的特例。
  2. 覆盖不同模型定位：π0.5 是强调开放世界泛化的基模，SmolVLA 面向高效低成本部署，给审稿人更强的通用性信号。
  3. 避免模型能力混淆归因：两基模的规模、训练分布不同，直接比较绝对值会把「模型强弱」混入「适配框架」的归因。正确做法是比较每个基模内部加入 Scan2VLA 数据后的处理效应（如节省率），再跨基模看趋势是否一致。
77真实演示节省率如何从学习曲线估计？

固定成功率阈值 τ，读取每条曲线的水平距离：Real-only 达到 τ 需 Nreal_RealOnly(τ)，Scan2VLA + Real 需 Nreal_Scan2VLA(τ)，节省率 Saving(τ) = 1 − Nreal_Scan2VLA / Nreal_RealOnly；用学习曲线插值 + bootstrap CI 估计，对数据抽样、训练种子、真机 episode 与插值过程联合 bootstrap。

78为什么图 4（学习曲线）是全文最重要的图？

因为论文核心主张是「真实数据效率」：零真实演示锚点直接展示适配可行性，曲线斜率与水平间距量化真实演示节省量。它比「3DGS 渲染更逼真」的视觉对比更能支撑贡献；正文不能为省篇幅移走主长程结果、核心 correlation 图或最强基线。

79表 3 分阶段结果如何解读？

每格报告 successes/trials 与 95% binomial CI，阶段从左到右累计；用于定位差异首次出现的阶段（P1–P4 哪一步开始掉队）。但必须与连续过程指标联合解释——两个方法二元结果相同时，抓取次数、篮子稳定性或放置质量可能仍不同。

80消融实验覆盖哪些组件？

自动实例 Mask vs 人工 GT Mask；有 / 无物体补全；有 / 无背景补全；有 / 无闭合碰撞几何；单场景 vs 多场景仿真数据；不同仿真数据规模。

81泛化实验覆盖哪些轴？

相对扫描姿态旋转 0–30°、30–90°、90° 以上三档；目标场景孪生适配与未见场景泛化分别报告；短任务到长任务（误差累积）也是一条泛化轴。

82效率与安全报告什么？

系统成本分场景采集、3DGS 优化、实例分解、双向补全、碰撞处理、轨迹生成与 RTX A6000 后训练时间；部署端在 RTX 5060 上分解图像采集、预处理、VLA 推理、动作转换、安全检查与端到端延迟，报告 mean/P95、策略频率与控制频率。安全事件（禁止碰撞、命令拒绝、陈旧状态超时、急停、人工干预）全部保留为任务失败。

83失败分析如何归因？

每个失败 episode 只分配一个首要阶段与原因：错选 / 感知、抓取、装篮、篮子端起 / 搬运、后备箱放置、VLA 超时、低层跟踪、安全拒绝、硬件 / 通信；报告计数、比例、是否动作前可发现、错误发生在真实观测还是补全 Gaussian 区域。

84统计单位为什么是 episode 而非图像帧？

图像帧在时间上高度相关，不是独立样本；独立统计单位是 episode（一次完整任务）。配对初始状态下，仿真与真实逐 episode 对应，才能做 sim-real 一致性统计。

85主终点、次终点与多重比较如何处理？

预注册严格长程 E2E 成功为主终点；物品完成度、掉落次数、篮子稳定性、后备箱最终位姿误差、任务时长为关键次终点；其余为诊断性过程量；确认性次终点做多重比较校正。二元结果用精确 binomial CI；连续指标报告单位、聚合层级、效应量与 bootstrap CI；方法比较用 mixed-effects 模型（数据条件与预算 = 固定效应；场景、物体、初始状态 = 随机效应）。

写作规则要求可检验的表述：必须报告成功次数、总试验数与置信区间。形容词无法被审稿人核查，是弱证据的包装；「主张—证据」原则是证据不足就缩小主张，而不是增加形容词。

93「主张—证据」原则如何约束标题与结论？

标题与结论中的每个概念（如「数据效率」「scene-native」）必须对应一个可检验终点（节省率、配对一致性、分解质量）。结果不足时缩小主张而不是加形容词；结论只能用统计支持的数字收束，并明确任务 / 场景 / 物体范围。

94为什么需要报告 successes/trials 与 CI，而不是只有均值？

成功率是比例型二元结果，只有均值无法判断统计可靠性；精确 binomial CI 让读者知道 95% 置信区间。这也防止「少量成功样本被包装成强结论」，是机器人学习实证规范（Kress-Gazit et al.）的要求。

95如何避免把单个本体结果扩写为多本体泛化结论？

结论明确写「AgiBot G2 上、饮料瓶抓取入篮与全身长程任务、这些场景与物体范围内」；把 formulation 的「与本体无关」与实证的「单本体验证」分开表述，不宣称覆盖所有机器人。

Part IX

九、局限与结论

96本文局限性有哪些？
  1. 原生 3DGS 保留采集条件下外观，不分离材质与照明；
  2. 大幅移动物体可能暴露生成表面，或保留烘焙阴影 / 高光；
  3. 透明、强反光、细薄或严重遮挡物体仍困难；
  4. 实例分割误差传播到补全与碰撞几何；
  5. 物理准确性依赖外部物性估计模块。
97结论如何收束？

用统计支持的数字收束：Scan2VLA-only 的 G2 成功率、sim-real correlation、真实演示节省率，附试验数与 CI；明确范围（饮料瓶抓取入篮、全身长程任务、场景与物体集合），不把单一本体扩写为多本体。

98用一句话总结 Scan2VLA？

一次原生场景重建 → 自动分解可移动物体并补全 + 绑定碰撞 → 生成交互式 Gaussian 数字孪生 → 在零真实 G2 演示下把通用 VLA 基模适配到未见 AgiBot G2，并用 sim-real correlation 与真实数据学习曲线量化适配可靠性与演示节省。

99审稿人最可能攻击的点是什么？如何应对？
  • 「不过是已有 Gaussian twin 系统的轻量组合」→ 用受控资产来源（Independent-GS 对照）+ 未见 G2 适配证据防守；
  • 「零真实演示是不是噱头？」→ 明确限定范围并披露全部冻结组件；
  • 「补全 / 物性依赖外部模块」→ 分层统计与消融证明各组件独立贡献；
  • 「单一本体」→ 结论边界写明，不做多本体宣称。
100下一步工作 / 未回答的问题是什么？

材料 / 照明分解（摆脱烘焙光照）；关节与软体物体扩展；多本体实证（把 embodiment-agnostic formulation 落到第二、第三个本体）；更大规模场景与物体类别；更复杂的交互（推、堆叠、动态场景）。
